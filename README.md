# 商いノート / sales-profit-tool

個人販売者・小規模EC向けの売上・利益管理ツール「商いノート」Ver.1.1です。CSVを読み込み、全体のKPI、SKU別集計、月別グラフを表示します。日本語UI、ライト／ダーク／OS連動表示、PC・iPad mini向けのレスポンシブレイアウトに対応しています。

## Ver.1.2：無料EC利益管理診断

静的サーバーの `/diagnosis/`（例：`http://localhost:8000/diagnosis/`）から利用できます。GitHub Pagesのプロジェクト配下でも動く相対リンクを使っています。既存ダッシュボードのHTML・CSS・JavaScriptや集計ロジックは変更していません。

- 1画面1問・全4問。所要時間の目安は30〜60秒です（実利用者の所要時間は未計測）。登録・メール入力不要。
- 販売チャネル、SKU別利益の把握、送料／手数料／広告費の管理、今の困りごとを選択。未回答では次へ進めません。戻る操作や結果からの「回答を見直す」で回答を保持しながら修正できます。
- 今の困りごとを最優先し、費用管理・SKU管理の未管理／一部管理の組み合わせで優先順を調整。改善ポイントは最大3件で、根拠となる回答と具体的な次の行動を示します。課題が少ない場合は継続的な確認を案内します。販売チャネルに応じた準備も表示します。
- 根拠のない点数・効果額・改善率は表示しません。自己申告に基づく参考情報であり、実際の経営状況の検証や成果保証ではありません。
- 「無料ツールを使う」で既存ダッシュボードへ移動します。無料ツールの集計対象は粗利益までで、送料・手数料・広告費は別途整理する旨を明示しています。
- 有料支援は9,800円の仮価格・提供準備中と案内するだけです。未完成の `/service/` へのリンク、申込・決済フォーム、個人情報の入力欄はありません。
- 回答はページ内のメモリーのみ。外部送信、Cookie／localStorage／sessionStorageへの保存、外部トラッキングは行いません。再読み込み・「最初からやり直す」で回答が消えます。
- OSのライト／ダーク設定に追従。ネイティブのラジオボタンでTab・矢印・Space操作に対応し、画面遷移時は質問／結果の見出しにフォーカスします。

診断用ファイルは `diagnosis/index.html`・`diagnosis/diagnosis.css`・`diagnosis/app.js`・`diagnosis/logic.js` に分離しています。将来のサービスページは、公開後に実在する相対URLを結果画面へ追加する想定です。

## Ver.1.1 の操作

- KPIはPC・iPad横画面で4列、iPhoneで2列。計算方法は折りたたんで確認できます。赤字は色と「赤字」の文字で示します。
- 月別グラフは「売上・粗利益」と「粗利益率」を切り替えられます。月をタップ／クリックするか、「確認する月」で選ぶと4指標の数値を確認できます。キーボードでは月にフォーカス後、Enter／Space／左右矢印で操作できます。
- 売上0円の月は利益率を0%に置き換えず、グラフに「—」、数値欄に「計算不能」と表示します。CSVにない月の数値は補完しません。
- SKU一覧は売上・粗利益・粗利益率・販売数量の高い順／低い順で並べ替えられます。同値ならSKU名順、計算不能の率はどちらの方向でも末尾です。
- SKUは1ページ50件。並べ替え後は先頭ページに戻ります。CSV出力にはページや並べ替えにかかわらず全件の集計を含めます。スマートフォンでは表と長いグラフを横スクロールできます。
- CSV読込成功時は件数・期間を表示し、エラー時は該当レコードと原因にフォーカスします。失敗したファイルの一部だけを集計せず、前回成功した結果を保持します。

## 起動

依存ライブラリのインストール、バックエンド、データベース、APIキーは不要です。Python 3で静的ファイルを配信します。

```sh
cd sales-profit-tool
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000` を開きます。Python 3がある環境では `npm start` でも同じサーバーを起動できます。ES Modulesとサンプルの取得を使用するため、HTMLの直接オープンではなくHTTPサーバーを使ってください。

「サンプルで試す」で表示を確認するか、「CSVを選択」で自分のファイルを読み込みます。「集計CSVを保存」で全体・SKU別・月別の集計を1つのCSVとして保存します。iPadではダウンロード後にSafariのダウンロード一覧／ファイルアプリで確認してください。

## CSV仕様

UTF-8（BOM付き可）、最大10MB。ヘッダーは下記の5列が必須です。列順は自由で追加列は無視します。値の前後の空白は除去し、空行は読み飛ばします。カンマ区切り・引用符内のカンマ／改行／二重引用符に対応します。

```csv
SKU,販売数量,販売単価,仕入原価,販売日
BAG-001,8,4800,2600,2026-01-12
CUP-002,15,1800,700,2026-01-20
```

- SKU：空欄不可。同じ文字列を同一SKUとして集計します。
- 販売数量：0以上の整数。
- 販売単価・仕入原価：0以上の数値。仕入原価は1個あたり。通貨記号・桁区切り・指数表記は使えません。
- 販売日：実在する `YYYY-MM-DD` 形式の日付。
- 不正な行はCSVレコード番号と理由を表示し、ファイル全体の集計を中止します。以前の集計があれば保持します。引用符内の改行は1レコードとして数えます。
- 重複したデータ行も別の取引として数えます。返品などの負数には未対応です。

## 計算

- 売上 = 販売数量 × 販売単価
- 売上原価 = 販売数量 × 仕入原価
- 粗利益 = 売上 − 売上原価
- 粗利益率 = 粗利益 ÷ 売上 × 100。売上0円では「計算不能」。

集計後の金額から粗利益率を算出します（行ごとの率の平均ではありません）。月別はデータがある月を昇順で表示します。金額表示は小数点以下最大2桁、率は1桁です。内部計算はJavaScriptの浮動小数点数を使うため小数に微小誤差が生じる場合があります。安全な計算範囲を超える金額はエラーにします。税・送料・手数料は含まず、会計／税務用途の厳密な小数計算は対象外です。

## 構成

- `index.html` / `style.css`：ダッシュボード、レスポンシブ／テーマ表示
- `js/data.js`：ファイル取得、CSV解析・検証、CSVシリアライズ
- `js/aggregate.js`：DOMや取得元に依存しない集計関数
- `js/app.js`：画面の状態・操作、ダウンロード
- `js/chart.js`：実データからの選択可能なSVGグラフ
- `js/presentation.js`：並べ替え、ページ分割、表示用の軸範囲・書式（集計処理から分離）
- `sample.csv`：8件・3SKU・4か月のサンプル
- `tests/sales.test.js`：既存CSV／計算ロジックの10件の回帰テスト
- `tests/presentation.test.js`：並べ替え・ページ分割・利益率グラフ等の10件のテスト
- `tests/browser_smoke.py`：任意実行のブラウザ回帰テスト

API連携を追加するときはデータ取得アダプターから `{sku, quantity, price, cost, date}` の配列を返し、同じ検証を経て `aggregateSales(rows)` に渡す構成にできます。

アップロードした内容は端末のメモリー内で処理し、外部送信・永続保存しません。リロードで消去されます。テーマ設定のみlocalStorageに保存します。SKUはHTMLとして解釈しません。出力CSVは引用符をエスケープし、ユーザー入力の表計算式の実行を抑止します。外部ライブラリ・フォント・CDNへの依存はありません。

## テスト

Node.js 22以降（開発時24.19.0）で実行します。

```sh
npm test
```

サンプルの期待値：売上342,000円、売上原価159,400円、粗利益182,600円、粗利益率53.4%、販売数量165点。ゼロ売上、赤字、小数、月／SKU集計、CSVの引用符・BOM・改行、不正入力、出力CSV、サイズ制限、計算範囲を検証します。

ブラウザでの確認手順：

1. 「サンプルで試す」で上記KPIと3SKU／4か月を確認。
2. 「集計CSVを保存」とサンプルCSVのダウンロードを確認。
3. 原価の空欄や不正な日付を含むCSVでエラーが出て、以前の集計を保持することを確認。
4. 売上0円のCSVで粗利益率が「計算不能」になることを確認。
5. テーマ切替、iPad mini 6の横画面（1133×744）・縦画面、PCで表とグラフを確認。
